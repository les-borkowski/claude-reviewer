# Reviewer v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. If those skills are not installed (e.g. a cloud session), work task by task in order, run each task's tests, and commit after each task.

**Goal:** Build v1 of the `reviewer` Claude Code plugin: `/reviewer:review` finds code in a local change that can be smaller without changing behaviour, and `/reviewer:stats` reports how its findings and improvements are used.

**Architecture:** Everything deterministic (diff scope, keep markers, tool runs, context pack, intent, merge, ranking, log, acted-on, stats) lives in one stdlib-only Python CLI, `scripts/reviewer.py`, so it is unit-tested. Judgement lives in prompts: an orchestrator skill, a `finder` agent (sonnet, run 2–5 times in parallel) and a `verifier` agent (opus). The skill calls the CLI between agent steps and passes JSON files around in `.reviewer/run/`.

**Tech Stack:** Claude Code plugin format (`.claude-plugin/plugin.json`, `skills/*/SKILL.md`, `agents/*.md`); Python ≥ 3.10 standard library only; tests with `unittest`; git via `subprocess`.

**Spec:** `docs/design.md` (read it first; this plan only adds the decisions the design leaves open). Standards the review applies: `standards/`. Research behind it: `docs/research-automated-code-review.md`.

## Global Constraints

- Python: standard library only, Python ≥ 3.10. No `pyproject.toml`, no third-party imports, including in tests.
- Tests: `python3 -m unittest discover -s tests -v` from the repo root. Tests that need git create throwaway repos in a temp dir; they never touch this repo's history.
- Never install or add a dependency to the **reviewed** repo. Static tools run only if already on `PATH` or declared by the reviewed repo (see Task 5). No `uvx`/`npx` downloads in v1.
- The review is report-only: it writes nothing in the reviewed repo except under `.reviewer/`. On first write it creates `.reviewer/.gitignore` containing `*`, so the reviewed repo's own `.gitignore` is never edited.
- Changed lines only: a finding outside the diff's changed line ranges is dropped.
- Finder count: 2 when `changed_lines < 100`, else 5; `--deep` forces 5.
- Large diff warning when `changed_lines > 400`.
- Minimum value: drop a finding when `lines_saved < 3` and `removes` is empty.
- Cap: show at most 5 findings; `--all` shows all kept findings.
- Agents pin their model in frontmatter: `finder` → `sonnet`, `verifier` → `opus`. (The author's global default model is haiku.)
- Lenses, exactly these five ids: `reuse` (reuse and stdlib), `abstraction` (unneeded abstraction), `dead` (dead code and unused options), `noise` (defensive noise and comments), `language` (language-specific rules).
- Rule ids come from `standards/*.md` headings (`### PY-02 ...`). A finding with a rule id not in the loaded standards is dropped.

## Data formats

These are the contracts between tasks. Paths are relative to the reviewed repo.

**Scope** (`reviewer.py scope` → stdout JSON):

```json
{"base": "<sha>", "base_kind": "last_review|merge_base|ref", "head": "<sha>",
 "branch": "feat/x", "changed_lines": 140, "large": false,
 "files": [{"path": "app/x.py", "lang": "python", "ranges": [[40, 52], [80, 81]]}],
 "skipped": ["package-lock.json"],
 "keep_markers": [{"path": "app/x.py", "line": 39, "rule": "CM-03", "reason": "port to billing API"}]}
```

`lang` is one of `python` (`.py`), `java` (`.java`), `typescript-react` (`.ts`, `.tsx`); other extensions are listed in `skipped`. Ranges are inclusive line numbers in the working-tree version of the file (added/modified lines only). Uncommitted changes are always included (diff of the working tree against `base`).

**Candidate** (written by each finder to `.reviewer/run/finder-<n>.json`, a JSON array):

```json
{"rule": "PY-02", "path": "app/x.py", "lines": [40, 52],
 "case": "the loop rebuilds Counter", "fix": "counts = Counter(words)",
 "lines_saved": 4, "removes": [], "preserves": "same dict contents and order",
 "source": "llm"}
```

`removes`: list of strings naming whole units the fix deletes (file, class, dependency, layer). `source`: `llm` or `tool:<name>`.

**Merged finding** (`reviewer.py merge` → stdout JSON): `{"findings": [...], "dropped": {...}}`. Each finding is a candidate plus `"id": "f1"` (`f` + 1-based index), `"votes": int`, `"lenses": [str]`. `dropped` has integer keys `missing_fields`, `unknown_rule`, `outside_diff`, `min_value`, `rule_switch`, `keep_marker`.

**Verdict** (written by the verifier to `.reviewer/run/verdicts.json`, a JSON array): `{"id": "f1", "keep": true, "confidence": 0.8, "reason": "...", "coverage": "tested|untested|unknown"}`. `confidence` is a float in `[0, 1]`; dropped findings may omit `confidence` and `coverage`.

**Log** (`.reviewer/log.jsonl`, one JSON object per line, append-only). Three record types:

- `{"type": "run", "run_id": "20261103T100000Z", "ts": "...", "branch": ..., "head": ..., "base": ..., "base_kind": ..., "changed_lines": ..., "finders": 5, "lenses": [...], "tools": {"vulture": "ran", "jscpd": "missing"}, "tool_hints": 3, "context_pack": {"symbols": 12, "truncated": false}, "intent": ["commits", "plan"], "dropped": {... merge keys ..., "verifier": 6}, "shown": 5, "coverage": {"tested": 2, "untested": 2, "unknown": 1}}`
- `{"type": "finding", "run_id": ..., "id": "f1", "rule": ..., "path": ..., "lines": [s, e], "source": ..., "lenses": [...], "votes": ..., "kept": true, "shown": true, "reason": ..., "coverage": ...}`
- `{"type": "acted_on", "run_id": ..., "id": "f1", "detected_in": "<run_id of the run that noticed>"}`

**Repo config** (`.reviewer/config.json`, optional): `{"disabled_rules": ["PY-04"]}`.

**Keep marker:** a comment containing `reviewer: keep <RULE-ID> <reason>` (any comment syntax; match the regex `reviewer:\s*keep\s+([A-Z]{2}-\d{2})\s+(\S.*)`). A marker with no reason does not match. A marker on line N suppresses findings of that rule in that file whose range includes N or N+1 (the marker sits on, or directly above, the code).

## Review Focus

1. **Nothing to review** (clean tree, branch equal to base): `scope` returns `files: []`, and the skill prints "Nothing to review" without dispatching any agent. Test in Task 3.
2. **Deleted, renamed and binary files in the diff:** deleted and binary files appear in `skipped`, renamed files are reviewed under the new path, no crash. Test in Task 3.
3. **No default branch to diff against** (no `origin/HEAD`, no `main`/`master`): `scope` exits with code 2 and the message `no base found; pass a ref: /reviewer:review <ref>`. Test in Task 3.
4. **A finder returns bad output** (not JSON, or a candidate missing `case`/`preserves`): the bad file or candidate is skipped and counted in `dropped.missing_fields`; the run continues. Test in Task 4.
5. **Corrupt or missing log** (a truncated last line, no `.reviewer/` yet): reads skip unparsable lines; `stats` with no runs prints `No reviews logged yet.`. Tests in Tasks 2 and 6.

### Task 4: Merge, filters and ranking

**Files:**
- Create: `scripts/reviewer_merge.py`, `tests/test_merge.py`
- Modify: `scripts/reviewer.py` (wire `merge`, `rank`)

**Interfaces:**
- Consumes: Scope (Task 3) for ranges and keep markers; `standards/` to collect valid rule ids.
- Produces:
  - `rule_ids(standards_dir: Path) -> set[str]` — ids from `### XX-NN` headings.
  - `merge(candidate_files: list[tuple[str, Path]], scope: dict, rules: set[str], disabled: set[str]) -> dict` — `candidate_files` is `(lens, path)` pairs; returns the Merged format. Order of filters per candidate: parse (bad file → count every candidate in it as `missing_fields`; unparsable file counts 1), `missing_fields` (`case`, `preserves`, `rule`, `path`, `lines`, `lines_saved` required), `unknown_rule`, `outside_diff` (no overlap with the file's ranges), `rule_switch`, `keep_marker`, then dedupe (same `rule`, same `path`, overlapping `lines` → one finding; keep the candidate with highest `lines_saved`; `votes` = number of distinct finder files; `lenses` = sorted distinct lenses), then `min_value` on the merged finding. Ids `f1..fn` in order of first appearance.

A finding without a verdict counts as dropped.
- CLI: `merge --scope FILE --standards DIR --finder LENS=FILE ...` (reads `.reviewer/config.json` if present); `rank --merged FILE --verdicts FILE [--all]` (cap 5 unless `--all`).

Only hints/lint on changed lines. A tool is used only if its executable is on `PATH` (`shutil.which`) **and**, for `jscpd`/`knip`/`eslint`, the reviewed repo's `package.json` lists it, or for `vulture`/`ruff`, `pyproject.toml`/`requirements*.txt` mentions it or it is on `PATH`. Adapters (each a small function, timeout 120 s, non-zero exit with no parsable output → `failed`):

    | Tool | Lang | Command | Output → |
    |---|---|---|---|
    | `vulture` | python | `vulture <files> --min-confidence 80` | text `path:line: msg` → hint `CM-01` |
    | `jscpd` | all | `jscpd --silent --reporters json --output <tmp> <files>` | `jscpd-report.json` duplicates → hint `CM-09` |
    | `knip` | typescript-react | `knip --reporter json` | unused exports/files → hint `CM-01` |
    | `ruff` | python | `ruff check --output-format json <files>` | lint |
    | `eslint` | typescript-react | `eslint -f json <files>` | lint |

    Java tools: `shortcut: no Java adapters in v1 (PMD/CPD need build config), add when a Java repo is reviewed.`
  - `build_context(repo: Path, scope: dict, budget_chars: int = 60000) -> dict` → `{"symbols": [{"name", "path", "line", "callers": [{"path", "line", "text"}]}], "index": [{"name", "path", "line"}], "dependencies": [str], "truncated": bool}`. Symbols: definitions on changed lines found by regex (`def`/`class` for Python; `function`, `const X = (`/`=> `, `class`, `export` for TS; method/class declarations for Java). Callers: `git grep -n -w <name>` excluding the definition line, max 20 per symbol. Index: every top-level function/class name in the repo for the scope's languages (`git grep -n -E` with the same regexes), for spotting reuse. Dependencies: names from `pyproject.toml` (`[project.dependencies]` and dependency groups), `requirements*.txt`, `package.json` (`dependencies`, `devDependencies`), `pom.xml` `<artifactId>`s. Truncate callers, then index, to fit `budget_chars` of JSON; set `truncated`.
  - `collect_intent(repo: Path, scope: dict) -> dict` → `{"sources": [...], "branch": str, "commits": [str], "plans": [{"path", "text"}]}`. Commits: `git log --format=%B <base>..HEAD`. Plans: files matching the branch slug (branch name after the last `/`) in `docs/**/*plan*.md`, `docs/superpowers/plans/*.md`, `.scratch/<slug>/**/*.md`; text capped at 20000 chars each. `sources` lists the non-empty ones of `commits`, `plan`.
- CLI: `tools --scope FILE`, `context --scope FILE`, `intent --scope FILE`, each printing its JSON.

**Files:**

**Interfaces:**
- Consumes: every CLI subcommand (Tasks 2–6) as `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/reviewer.py" <cmd> --repo .`; agents from Task 7.
- Produces: the skill `review` (invoked `/reviewer:review [ref] [--deep] [--all] [--full]`).

Frontmatter: `name: review`, description "Pre-PR simplification review of local changes: finds code that can be smaller without changing behaviour, checked against written per-language rules. Report only. Use for /reviewer:review, \"review before PR\", \"can this be simpler\"." Body, in order (the step numbers match `docs/design.md`):

1. **Scope:** `scope` → `.reviewer/run/scope.json` (clear `.reviewer/run/` first; generate `run_id` as UTC `YYYYMMDDTHHMMSSZ`). Exit 2 → show its message and stop. `files == []` → print `Nothing to review.` and stop. Then `acted-on --run-id <run_id>`.
2. **Prepare:** concatenate `standards/common.md` + the file per language present (`python.md`, `java.md`, `typescript-react.md`) from `${CLAUDE_PLUGIN_ROOT}/standards/` into `.reviewer/run/standards.md`, then append the reviewed repo's `CLAUDE.md` and `CONTRIBUTING.md` (if present) under a heading stating they win on conflict. Run `tools`, `context`, `intent` into `tools.json`, `context.json`, `intent.json`.

5. **Verify:** dispatch one `verifier`; then `rank` (with `--all` if given) → `ranked.json`.
6. **Report:** follow `report-format.md` exactly.
7. **Log:** write the run record (Log format; `dropped.verifier` from `rank`; `shown`; `coverage` counts over shown findings) and one finding record per merged finding (`kept`, `shown`, `reason`, `coverage` from verdicts), then `log-run`.

     - **Problem:** ...
     - **Fix:** ...
     - **If we skip it:** ...

- Then `<k> more kept findings not shown (use --all).` when applicable; `Dropped: <n> by verifier, <m> below minimum value, <p> by keep markers/rule switches.`
- Last lines: `Lean: -<sum of shown lines_saved> lines possible.`, `Verdict: ship.` (no shown findings) or `Verdict: apply <ids> first.` (findings with confidence ≥ 0.7), and `Missing: ...` naming any of: no tools ran, no intent found, context pack truncated (omit the line if none).
